The purpose of this simulation is to demonstrate how changes in process assumptions can impact overall performance of the system. No information is collected, everything is running solely in your local browser.

You start by configuring the organization through the Teams and handoffs section. You can add teams, set their work stages, and define how work is handed off between them. The Editor can be hidden to give more space to the simulation view.

You can configure the simulation parameters in the Parameters section. Hover over the parameter fields to see a description of what they mean. Once you have configured the teams and parameters, you can save and later reload configurations. It is possible to have multiple configurations saved in the browser, and you can switch between them at any time.

In the Process flow section you can see how teams are interacting with each other and a live view of how work is moving through the system. If a work item is dependent on multiple teams, it will be blocked until all teams have completed their work. There you also see the current simulation time, which is measured in days.

The Lead time and processing ratio chart shows the lead time of each work item on the horizontal axis, and the processing ratio (processing time divided by lead time) on the vertical axis. The size of each bubble represents how many work items are represented by that point. The chart is updated in real-time as the simulation runs.

Click Start simulation to see how work flows through the system.

Known issues:
  • Processing time is currently not correctly calculated for work items that are blocked by multiple teams. It will show the sum of the processing times for all teams involved, which leads to an overestimation of the actual processing time.
  • The simulation output will make the screen "jump" up and down a bit during execution. This is due to how the team view is adjusted, based on work items processed in each team stage.
